## 질문 (개발 세션 → 관리 세션)

- 계좌 블록: 그룹이 1개뿐이면(회비 계좌 등) 처음부터 펼침. 2개 이상이면 PLAN대로 접힘
- 계좌 블록: 복사 내용은 '은행 계좌번호'(예: `카카오뱅크 3333-00-0000001`) — 은행 앱 붙여넣기 인식용. 토스 은행 이름은 주최자 입력 그대로(편집기에서 짧은 이름 목록 추천)
- 카카오페이 링크 형식은 저장 때 막지 않고(입력 중 자동 저장이 실패하지 않게) 하객 화면에서 `https://qr.kakaopay.com/`으로 시작할 때만 버튼을 보임
- 안내 블록: 항목 최대 6개. 버튼 링크는 http(s) 주소일 때만 보임(저장은 막지 않음). 전화번호 자동 링크는 더 긴 숫자(계좌번호 등)의 일부면 건너뜀
- 참석 질문: 선택형은 하나만 고르기(복수 선택 없음). 보기 최대 8개, 짧은 글 100자, 숫자 0~999. 대상에 안 맞거나 없는 질문의 답은 서버에서 버림
- 대시보드 선택형 집계는 '응답 건수' 기준(인원 합계 아님). 보기 문구를 나중에 바꾸면 예전 답은 '기타(바뀐 보기)'로 셈
- CSV: 열 = 이름 · 참석 · 인원 · (식사) · 질문들 · 응답 시각(KST), 오래된 응답부터. =, +, -, @ 로 시작하는 칸은 앞에 ' 를 붙여 엑셀 수식 실행 방지
- 행사 종류: DB enum은 끝에 값만 추가(`ADD VALUE IF NOT EXISTS`), 화면 순서는 `EVENT_TYPE_ORDER`(결혼 · 송년회 · 청첩장 모임 · 돌 · 생일 · 집들이 · 회식 · 기타). 기존 '돌잔치 · 생일' 부제는 '첫 생일 잔치'로
- 템플릿: 결혼 · 돌에 계좌 · 안내를 이번에 넣고, 캘린더 · 연락하기는 해당 블록(⑦ · ⑧)을 만들 때 추가. 송년회 메뉴 질문 예시 외에 '2차도 가요?' 질문도 넣음. 계좌번호 자리는 비워 둠(빈 계좌는 하객 화면에 안 보이고 발행 전 안내)
- 카톡 카드: 직접 지정 사진도 사진 한도(10장)에 포함. 카드 사진 → 표지 → 사진첩 → 행사 종류 기본 이미지 순. `?go=rsvp`로 열면 참석 칸으로 스크롤하고, 아직 응답 안 했고 마감 전이면 응답 폼을 바로 엶
- 캘린더: D-day는 보는 사람 브라우저의 한국 날짜 기준으로 계산(서버 렌더링과 어긋나지 않게). 행사가 지나면 D-day와 저장 버튼을 숨기고 달력만 남김. .ics는 `inline`으로 내려 iOS가 '캘린더에 추가'를 띄우게 함, 장소는 첫 번째 장소 블록
- 결혼 · 돌 템플릿 순서: 표지 · 인사말 · 사진첩 · 캘린더 · 장소 · 참석 · 연락하기 · 계좌 · 안내 (· 방명록). 연락하기는 관계만 미리 채우고 번호는 비워 둠
- 나도 만들기: 서버가 원본에서 읽는 건 행사 종류 · 테마 · 블록 종류/순서/숨김 여부뿐(config는 select 안 함). 같은 종류 블록이 템플릿보다 많으면(장소 2개 등) 남는 건 빈 기본값. 원본이 발행 상태가 아니면 일반 /new로. `showMadeWith`가 꺼지면 '나도 만들기' 카드와 하단 문구가 함께 숨고 '친구에게 공유'는 남음
